# お題5：本人確認の有無（UVフラグ）と二要素認証

## 目的

- UV フラグが何を表すかを理解する
- UV を必須にするにはサーバーでの検証が必要なことを理解する
- 検証の設定を途中で緩めさせない実装を知る
- UV フラグの限界を理解し、二要素認証を省略してよいかを考える

## 講演との対応

意思決定4（パスキーと二要素認証）。UV（User Verified）フラグは認証器の自己申告である点。

UV フラグは、認証器が指紋・顔・PIN などで本人確認をしたかどうかを表す。
`user_verification` の値は、required＝本人確認を必ずする、preferred＝できればする、discouraged＝しなくてよい、という意味。

## AIへの指示例

> `user_verification` を required / preferred / discouraged で切り替えられる設定を追加し、ログイン結果画面に UV フラグの値を表示して。required のときは、UV なしの認証ではサーバー側でログインを拒否して。
> 本人確認をしない認証器を再現するため、「ブラウザには discouraged と伝え、サーバーだけ UV を必須にする」設定も追加して

## 確認方法

仮想認証器はいつもの設定（user verification オン）のまま、設定を切り替えてログインする。

| 設定 | 期待する結果 |
| --- | --- |
| preferred | ログインできる。UV フラグ = true |
| discouraged | ログインできる。UV フラグ = false（本人確認なしでログインできてしまう） |
| required | ログインできる。UV フラグ = true |
| ブラウザには discouraged・サーバーだけ required | サーバーが UV フラグを検証して、ログインを拒否する |

そのうえで「本人確認なしでログインできることをどう考えるか」「UV フラグは認証器の自己申告だが、それでも二要素認証を省略してよいか」を議論する。

> Chrome の仮想認証器で「Supports user verification」をオフにすると、ユーザーネームレスのログインそのものが拒否されてしまい、本人確認なしの認証を試せません。そのため discouraged を使って本人確認なしの認証を再現します。
