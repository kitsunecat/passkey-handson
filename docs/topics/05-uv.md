# お題5：本人確認フラグ（UV）と二要素認証

## 目的

- 本人確認フラグ（UV）が何を表すかを理解する
- 本人確認を必須にするにはサーバーでの検証が必要なことを理解する
- 検証の設定を途中で緩めさせない実装を知る
- 本人確認フラグの限界を理解し、二要素認証を省略してよいかを考える

## セッションとの対応

セッションの「パスキーと二要素認証」の話。本人確認フラグが認証器の自己申告であることを確かめ、パスキーでログインしたときに二要素認証を省略してよいかを考えます。

本人確認フラグ（UV：User Verified）は、認証器が指紋・顔・PIN などで本人確認をしたかどうかを表す。
`user_verification` の値は、required＝本人確認を必ずする、preferred＝できればする、discouraged＝しなくてよい、という意味。

## AIへの指示例

> `user_verification` を required / preferred / discouraged で切り替えられる設定を追加し、ログイン結果画面に本人確認フラグ（UV）の値を表示して。required のときは、本人確認なしの認証ではサーバー側でログインを拒否して。
> 本人確認をしない認証器を再現するため、「ブラウザには discouraged と伝え、サーバーだけ本人確認を必須にする」設定も追加して

## 確認方法

仮想認証器はいつもの設定（user verification オン）のまま、設定を切り替えてログインする。

| 設定 | 期待する結果 |
| --- | --- |
| preferred | ログインできる。本人確認フラグ = true |
| discouraged | ログインできる。本人確認フラグ = false（本人確認なしでログインできてしまう） |
| required | ログインできる。本人確認フラグ = true |
| ブラウザには discouraged・サーバーだけ required | サーバーが本人確認フラグを検証して、ログインを拒否する |

そのうえで「本人確認なしでログインできることをどう考えるか」「本人確認フラグは認証器の自己申告だが、それでも二要素認証を省略してよいか」を議論する。

> Chrome の仮想認証器で「Supports user verification」をオフにすると、ユーザーネームレスのログインそのものが拒否されてしまい、本人確認なしの認証を試せません。そのため discouraged を使って本人確認なしの認証を再現します。
