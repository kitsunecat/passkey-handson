# お題3：ユーザーネームファースト vs ユーザーネームレス

## 目的

- ログインするユーザーを特定する2つの方式の違いを理解する
  - ユーザーネームファースト：先にメールアドレスを入力し、そのユーザーのパスキーでログインする
  - ユーザーネームレス：メールアドレスを入力せず、認証器にあるパスキーを選ぶだけでログインする
- ユーザー情報ごと認証器に保存されるパスキー（Discoverable Credential）の役割を理解する
- ユーザーネームファーストで気をつけることを知る
- 方式を選ぶときの判断材料を知る

## セッションとの対応

セッションの「ログイン時にユーザーをどう特定するか」の話。2つの方式の違いと、ユーザーネームレスを実現する Discoverable Credential を試します。

## AIへの指示例

> メールアドレスを先に入力し、そのユーザーのパスキーだけを `allowCredentials` に指定してログインする方式を追加して。既存のユーザーネームレス方式も残して。
> Discoverable Credential に対応していない認証器でも登録できるよう、登録時の `resident_key` は `preferred` にして

## 確認方法

仮想認証器で「Supports resident keys」をオフにした認証器で登録し直すと、

- ユーザーネームレス（「パスキーでログイン」ボタン）ではログインできない
- ユーザーネームファースト（メールアドレスを入力してログイン）ではログインできる

> ベースのアプリは登録時に `resident_key: "required"` を指定しているため、そのままでは「Supports resident keys」がオフの認証器で登録できません。
