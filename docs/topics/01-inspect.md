# お題1：中身を覗く（全員）

## 目的

サーバーに届くのは公開鍵と署名だけであること、チャレンジによってリプレイ攻撃が防がれることを確認する。

## 講演との対応

登録フロー・認証フロー、チャレンジの説明。

## AIへの指示例

> 登録時と認証時に、サーバーが生成したオプションと、ブラウザから届いたデータ（クレデンシャルID、AAGUID、UP/UVフラグ、sign_count）をわかりやすく画面とログに表示して。同じ認証データをもう一度送る『リプレイ』ボタンも付けて

## 確認方法

- 秘密鍵はどこにも出てこないこと
- ログインのたびに sign_count やチャレンジが変わること
  - 仮想認証器は sign_count を1ずつ増やします。iCloud キーチェーンなど同期されるパスキーは常に 0 のことがあります
- リプレイボタンでは検証が失敗すること

## 補足：AAGUID

仮想認証器を2つ作ってそれぞれで登録すると、AAGUID が同じ値になります。
AAGUID は個人ではなく、認証器の「種類」を表す ID です。SmartHR はこれを認証器名に変換して、パスキーの初期名にしています（意思決定6）。
